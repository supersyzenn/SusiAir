# Daily-hours Logbook Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline. Steps use checkboxes for progress.

**Goal:** Replace the Logbook placeholder with an authenticated daily-hours history based on real API data.

**Architecture:** Add metadata/statistics to the existing Nest daily-hours response; Nuxt renders a bounded monthly history with API-owned totals.

**Tech Stack:** Existing Nuxt 3, Pinia, SCSS, NestJS, Jest, Playwright and axe.

**Spec:** `docs/superpowers/specs/2026-10-29-logbook-design.md`

## Global constraints
- Local only; business date defaults to 2026-05-15.
- No invented per-flight fields, write endpoints, database or frontend seed data.
- Existing endpoint consumers retain from/to/days behavior.

## Review focus
- Current month must stop at the business date, not display projected future records.
- Empty/zero-hour ranges must not divide by zero or appear as missing API data.
- Month navigation must obey source bounds and ignore stale responses.
- Dates and month boundaries use UTC date-only arithmetic.
- API outages, session expiry and small screens remain usable.
